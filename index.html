  • 근거가 없으면 답하지 않는 챗봇FAQ 키워드, FAQ 임베딩, 약관 벡터 순으로 세 단계를 검색하고, 모두 기준에 못 미치면 답을 만들지 않고 담당자 문의로 안내합니다. 직원용 매뉴얼은 권한에 따라 고객에게 노출되지 않습니다.
  • 깨져도 되돌릴 수 있는 이체타행 정산이 실패하면 출금을 되돌리는 거래가 자동으로 쌓이고, 같은 요청이 두 번 오면 한 번만 처리합니다. 메시지 큐가 멈춰도 같은 처리를 서버 안에서 이어갑니다.
  • 왜 의심스러운지 말해 주는 이상거래 탐지규칙 8개와 이상치 탐지 모델 점수를 합치고, 기준을 넘으면 LLM이 의심 사유를 고객이 읽을 수 있는 문장으로 설명합니다.
  • 같은 질문은 모델을 다시 부르지 않기질문 캐시로 응답을 1,812ms에서 1ms로 줄였고, 모든 호출의 토큰·지연·프롬프트를 남겨 나중에 다시 볼 수 있게 했습니다.
  • 데이터를 더 넣는다고 좋아지지 않았다약관만으로는 부족해 은행 업무 매뉴얼을 직접 써서 넣고 공개 자료까지 더해 1만 2천 청크로 늘렸지만 Faithfulness는 그대로였습니다. 검색 방식을 바꾸는 쪽으로 보고 있습니다.
  • 모호한 질문을 단정하는 문제"이체 어디서 해?"에 자동이체 화면으로 바로 보내는 것을 발견했습니다. 대상이 여럿이면 선택지부터 보여주도록 고치는 중입니다.

  • 장애 자동 분류와 재처리 이력시간 초과, 인증, 형식, 서버 오류로 나눠 알림을 보내고, 재처리한 호출은 원래 호출과 이어서 추적합니다.
  • AI 키가 없어도 돌아가는 원인 분석LLM 키가 있으면 RAG로, 없으면 TF-IDF 유사 사례 검색으로 자동 전환해 어떤 환경에서도 시연이 끊기지 않습니다.

데모는 합성 데이터로 동작하며 실제 계좌 정보는 포함되지 않습니다.

  • 예측은 나중에 스스로 채점하기7·14·21영업일 뒤 가격을 예측하고, 기간이 지나면 실제 결과로 채점합니다. 8,938건을 채점해 보니 방향 적중률은 46%로 동전 던지기 수준이었고 범위 적중률은 83%였습니다. 그래서 챗봇이 예측을 말할 때 과거 적중률을 함께 밝히게 했습니다.
  • 챗봇의 말도 채점하기챗봇이 답변에서 한 매수·매도 판단을 자동으로 기록하고, 21일 뒤 실제 가격으로 맞았는지 매깁니다.
  • 검증 없이 실돈을 맡기지 않기전략은 모의 계좌에서 먼저 돌려보고, 실계좌 자동 집행은 기본으로 잠가 두어 사용자가 직접 켜야만 동작합니다. 모호한 종목명은 임의로 고르지 않고 되묻습니다.
  • 데이터에 없으면 없다고, 모호하면 되묻기"삼성"처럼 대상이 여럿인 질문은 후보를 보여주고 되묻고, 근거 데이터가 없는 질문은 없다고 먼저 밝힙니다. 직접 10개 질문으로 검증해 금액 단위 오류, 답변 잘림, 범위 밖 질문 응대를 찾아 고쳤습니다.
